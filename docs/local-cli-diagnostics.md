# 本地 CLI、预览同步与 NPM 工具诊断

日期：2026-11-05。主要检查 Codex CLI。优先级中 P1 表示可能造成文件覆盖或任务静默失败，P2 表示兼容性、性能或诊断质量问题。

## 当前策略：正常开发无默认次数或整轮预算

后续用户明确要求解除运行次数限制，并保留单次超时、连续三次超时后才失败。下面的当前策略替代本文早前“保留 30 次上限”的方案；历史诊断证据仍保留。

| 原限制                                                  | 当前行为                                                                                      |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 本地工具默认 30 次，Native 最多 512 次                  | 正常请求发送 `maxToolCalls: 0`，表示无限；省略字段也为无限，不再存在 512 ceiling              |
| API 默认 30 次模型迭代，最后一轮要求停止                | 默认无限迭代，由模型自然结束、用户停止或真实错误终止；移除最后一轮强制收尾指令                |
| 子代理默认 10 轮、Design Review 20 轮                   | 正常内部入口不传有限预算                                                                      |
| Local 每轮最多派发 3 次子代理                           | 解除累计派发次数限制                                                                          |
| API 同次响应只接受 3 个子代理                           | 所有请求分批排队执行，最多同时 3 个；不丢弃第 4 个及之后的请求                                |
| 原型项目最多自动继续 3 批                               | 按蓝图检查点持续推进至完成；每批前验证当前运行，Stop 后不再发新请求；原样返回时明确报告未推进 |
| Local 整轮最多 30 分钟                                  | 移除整轮截止，保留主动 Stop、应用退出和错误时的有限资源清理                                   |
| Local 累计文本/思考 16 Mi 字符，协议 32 MiB/250000 事件 | 正常生成不再因累计内容或事件数量中断；探测输出、单帧解析及大小校验继续有效                    |
| 桌面 SSE/MCP 流累计时长、字节数、瞬时速率触发断流       | 移除这些截断式预算；逐块转发、ACK 背压与无响应故障检测继续有效                                |
| Antigravity 主运行/图片 `--print-timeout 30m`           | 显式传 `0s`，避免遗漏参数后退回某些已安装版本的有限默认值                                     |

Antigravity 参数语义依据[官方 headless 文档](https://antigravity.google/docs/cli/headless/#flag-reference)。本机只读 help 接受 `0s`，没有发送模型请求验证长时间运行。外部 CLI 旧版本的隐藏时限和模型服务商的配额/上下文限制不由本应用控制。

显式编程参数 `maxIterations` / 正数 `maxToolCalls` 保持兼容，用于调用方主动选择有限预算；正常开发、子代理与独立审查路径均没有默认预算。旧预算错误记录和对应继续提示仍可解析。

### 单次超时：最多三次机会，不重放已执行副作用

- API 模型请求保留 SDK `maxRetries: 0`，应用默认最多两次额外重试，即总共三次尝试，避免两层重试叠乘。
- 只读 HTTP 查询仅在本次计时器真正到期时重新请求，最多三次；外部取消、权限或普通非超时失败不因这项策略重放。支持将 NPM 响应正文读取纳入同一 deadline。
- Host 工具、MCP、图片和技能脚本沿同一个已派发请求/进程继续等待，前两个超时窗口不重发，第三个窗口才取消并清理。超时不表示远端已经停止；保留同一次执行可避免重复写文件、重复授权脚本或重复消耗图片额度。
- Codex 的 MCP 等待时限与 Host 三个工具窗口对齐；新建和恢复会话使用相同配置。
- 预览 ready、导航和截图沿同一个 generation、nonce、requestId 等待三个窗口；过期运行立即失效。截图库沿同一次脚本下载等待三个窗口，不重新插入脚本、不重新截图或重建预览，Stop 后没有新增自动资源请求。
- 流读取的无数据检测和消费者 ACK 也最多等待三个窗口；持续有数据的连接没有累计开发预算。
- 手动 Stop 仍立即传播，不等待第三个窗口；权限拒绝、无效协议、输入错误和真实进程失败仍按原类别处理。

取消上限同时修复了 Stop 边界：API 在整轮复用取消信号，工具结束后不再通过新建 controller 恢复请求；迟到的可写子代理结果必须通过原运行的 signal 检查才可提交；未开始的工具调用补齐取消结果，后续继续时保持工具消息配对完整。本地平台能力检查前即建立本轮取消信号，检查期间 Stop 后不再启动 CLI，也不误报故障。原型首轮自动续批增加当前运行校验，防止点击 Stop 后补发批次。

原型项目没有自动批次数上限，但自动继续返回后，若检查点仍未完成且所有 ProjectFiles 的键和值均完全相同，会明确报告“未推进”并保留当前项目。此检查不限制持续有进展的长任务，也不检查最初的研究阶段，防止模型已自然结束却没有更新项目时反复发起相同的收费请求。

没有解除工具权限、单个对象大小/结构验证、连接资源并发和进程树隔离。这些边界不会按正常运行已累计的调用次数或总时长消耗预算。

连接建立、MCP 工具目录发现和资源关闭各自的故障检测继续保留；三次执行机会不将权限错误或非超时业务错误改为自动重放。

### 本轮验证

- 本地 Generator 与真实 Native Broker 均覆盖 600 次工具调用；实际 Pi 子进程流覆盖 250001 条事件、超过旧 32 MiB 阈值。它们是正式回归和本地 fixture，不是 600 次真实模型调用。
- API 模型 mock 连续完成 35 次工具轮次后自然结束；同一响应 7 个子代理全部执行、最大并发 3。子代理默认无迭代预算，Design Review 不再传 20 轮限制。
- 原型首次生成和手动继续均通过超过旧上限的 6 批进度回归；未推进、Stop、显式预算或取消终态各自正确处理。
- 虚拟时间超过 31 分钟的 Native 任务仍运行；响应流累计 75 MiB、虚拟时间 150 分钟也正常推进。Stop、源错误与消费者失效仍能结束任务。
- Host、真实 MCP SDK 的内存 HTTP fixture、stdio echo、真实本地脚本/图片 fixture 均验证第二窗口成功或第三窗口失败，副作用只执行一次。HTTP 前两次超时第三次成功、最终超时、正文挂起及 Factory→fetch 取消链路均有回归。
- 最终前端全量 **215 套、1441 项通过**；Rust 全量 **300 项通过、2 项显式手动真实 CLI 测试忽略**。类型检查、lint、构建、桌面安全检查、Prettier、Rust fmt 和 diff 检查通过。构建保留既有 MCP store 混合导入提示，Vitest 有 jsdom Canvas 未实现提示，均不影响通过。未调用真实模型，未执行本轮桌面长任务或浏览器 E2E。
- 测试启动的本地 fixture 进程和临时目录均已清理，本轮未启动额外预览服务或生成 Docker 镜像，也未执行 git commit。包含 Rust 修改，需重启桌面开发进程或重新构建应用加载当前行为。
- Terra 做限制盘点，Sol 做只读设计和最终复审，三个 Astra 分别处理 Native、API/MCP/脚本、HTTP/Preview；主代理完成本地 Generator、原型续批、响应流/共享等待、集成与最终验证。

## 18:36 截图事故：工具预算停止被误报为 CLI 退出

诊断 ID：`43ac5212-b09f-4cba-9901-bf79cbd8d814`。只读匹配本机 WebKit IndexedDB 中的错误记录，时间为 2026-11-05 18:36:26（北京时间）；`processExit / stream / manual`，`hadActivity` 与 `hadHostSideEffect` 均为 true。用户确认一直停留在原会话，没有主动停止。对应 Codex 0.163.0 原生记录约从 18:26:40 开始，最后一个 `read_files` 请求位于 18:36:26.653；运行约 9 分 46 秒，没有达到整轮 30 分钟时限。

### 触发条件与证据

父运行已完成 **30 次 Host 工具调用**，第 31 次 `read_files` 没有返回结果。这与默认 30 次预算及 Native Broker 的拒绝位置吻合，属于高置信度的直接触发条件。原始 Native 失败详情没有被持久化，因此不能声称从历史记录直接读到了 `BudgetExhausted`，也没有网络或配额错误的独立证据。

| 父运行工具                 | 已完成次数 |
| -------------------------- | ---------: |
| `list_files`               |          1 |
| `read_skill`               |          8 |
| `read_files`               |          3 |
| `get_console_logs`         |          2 |
| `submit_design_contract`   |          1 |
| `dispatch_subagent`        |          1 |
| `patch_file`               |         10 |
| `project_health_check`     |          1 |
| `capture_preview_evidence` |          1 |
| `measure_preview_layout`   |          1 |
| `audit_accessibility_tree` |          1 |
| **总计**                   |     **30** |

注意：首次读取技能使用数组 `.map` 实际发起 5 次调用，不能只计源码中的一次函数引用。上述 30 次均为父运行，未将子代理独立预算混入统计。

### 误分类链

1. 第 30 次调用成功后，前端只设置 `budget.exhausted = true`，仍将工具结果返回 CLI。
2. CLI 继续请求第 31 次调用，Native Broker 在发出 `ToolRequest` 之前拒绝并取消共享 token；前端的预算停止分支来不及执行。
3. `RunSupervisor.finish` 也无条件取消同一 token，用于及时撤销 Host 工具权限。
4. Native 在收尾后根据这个 token 判断运行是否被主动取消，将原始错误改为 `Cancelled`。
5. 前端没有收到用户或应用主动停止信号，因而把它转换成截图的通用 `processExit`。UI 只按类别显示“进程退出”，无法反映预算或其他原始原因。

第 3～4 步还会影响审批、协议、凭证等非预算失败，不能仅修提示文案。

### 修复与验收

- 分离 Stop 父 token 与 Provider/Broker 共用的 authority 子 token。收尾仍立即关闭工具权限；只有真实主动停止设置 Stop，原始错误保持原类别。
- Broker 在撤销权限前记录首个固定失败原因；普通 unregister 不覆盖它。现有错误事件和失败对象字段不变，仅增加明确的 `toolBudgetExceeded` 类别。
- 仅此预算类别转换为现有 `maxIterationsReached` 受控收尾。保持 30 次上限，保留部分回复、工具结果和已提交文件；不自动续跑。其他桥接、权限、协议错误仍走故障链。
- UI 显示“本轮工具调用已达到上限，生成已暂停。项目修改已保留，发送‘继续’可接着完成”，状态回到 idle，不标记任务成功完成。
- 旧 `processExit` 记录只精确翻译 Host 已知的受控摘要，区分限流与原因未保留的中断；不展示任意 Provider 文本。
- Rust 真实 Broker 回归先完成 30 次调用，再确认第 31 次没有 `ToolRequest` 或 Host 副作用，并获得独立预算类别。修改前返回 `toolBridgeFailed`，修改后通过。
- 真实本地子进程回归确认 Supervisor 结束审批失败后，原始 `ProviderApprovalRejected` 得到保留；修改前错误变为 `Cancelled`。同时覆盖正常完成、显式 Stop 与晚到工具权限撤销。
- TS 回归先复现预算错误被抛出、UI 缺少继续提示，修改后确认 30 次调用后的文件/部分文本保留、没有自动重放、手动新一轮可继续；相同英文文案的普通 `toolBridgeFailed` 仍报错。

本次追踪没有发送真实模型请求，也没有自动重放用户任务。修复后真实 CLI 再次达到预算的桌面验收尚未执行；正式回归证明了对应 Broker、Runtime、Generator 与 Hook 路径，不替代这项真实运行验证。

本次增量验收：16 套相关 Vitest、183 项通过；`cargo test --lib` 全部 275 项通过、2 项显式手动真实 CLI 测试保持忽略；类型检查、lint、Vite 构建、Prettier、Rust fmt 和 diff 检查通过。Sol 只读复审生命周期与预算边界，Astra 修复 Native 取消归因，主代理完成事故取证、预算终态/UI、集成和最终验证。没有启动服务或生成 Docker 镜像，没有提交代码。Rust 修改需要重新启动桌面开发进程或重新构建应用才能加载。

## 真实桌面发现的静态预览问题

使用本机 Codex CLI 0.163.0 和隔离标识的 Tauri 验收包，两轮真实请求创建并修改 `index.html`。第二轮结束后，代码编辑器已是 `CLI_PREVIEW_UPDATED_20261105`，iframe 仍显示 `CLI_PREVIEW_BASELINE_20261105`；软刷新和手动 `client.updateSandbox` 都未恢复页面。解码客户端的二进制文件 Map 后确认其中也包含新文本。控制台多次报告 static-browser-server relay 的 BroadcastChannel 请求等待超时。这是独立于过期反写的前向预览故障，不能用组件文件状态正确来宣告 iframe 正确。

仅在**桌面端、启用预览、static 模板**时，增加稳定的 `customSetup.environment = "parcel"`，使用 SandpackRuntime 避开该静态 Service Worker/relay 通道。网页端 static、React/Node 模板和 code-only 均保留原有选择。模板、项目文件和导出内容不变，不逐次文件更新重建 Provider。

接口依据：[Sandpack 官方 Client 文档](https://sandpack.codesandbox.io/docs/advanced-usage/client)、[官方 customSetup 说明](https://sandpack.codesandbox.io/docs/getting-started/usage#fully-custom-setup)。同时核对已安装包的 `combineTemplateFilesToSetup` 和客户端选择源码。新增真实 Provider 环境矩阵，桌面 static 用例先失败后通过，其余平台与模板作为对照。

### 已实施的补充语义

- API 在完整 assistant/tool 结果组闭合后，将补充作为真实用户消息加入下一模型请求；重试保留原请求快照。
- Codex、Claude、Pi、Antigravity 使用同一个 Host 工具回包通道：当前工具正常完成后附带补充；没有 Host 回包时，在当前 CLI 轮自然结束后接续。接续共享原预算，保留已完成工作。
- 文字、附件与显式技能均可追加。仅选技能时生成非空的明确用户指令。当前模型、模式、项目权限及 MCP 范围不会因补充隐式切换。

- Stop、切换、重置及重新加载会取消旧队列，不自动恢复生成。取消项可恢复到输入框，用户再次发送才产生新 ID；附件引用继续保留。
- 本地传输 envelope 的顶层补充只能由 Host 队列构造。外部工具结果整体嵌套为数据；同名字段不能创建补充、激活技能或扩大权限。envelope 不复制进工具卡及 canonical 工具正文。

## 2026-11-05：输入框与即时对话展示修订

本节更新上轮实现的界面行为，取代上文“同时显示两个运行按钮”和“特殊补充卡片”的描述。

- 输入框由 16px 缩小为 14px、20px 行高。WebKit 实测在 1280px 与 390px 视口下均为此值。
- 输入区仅保留一个主动作：运行中没有可发送内容时显示进行/停止；有文字、已准备好的附件或显式技能时切换为发送。附件处理中及提交处理中继续保留停止能力；空闲时沿用普通发送按钮。
- 新要求立即复用 `MessageBubble` 的普通用户气泡，加入同一滚动和虚拟列表，显示文字和附件；移除专门的补充卡片、标题和操作按钮。独立提交的要求保持为独立消息。
- 接收时记录可选 `afterMessageIndex` 展示位置；停止后保留的消息不会因后续新任务而漂移至对话末尾。旧记录没有位置时保留原有末尾展示回退。
- 普通气泡投影只服务于展示。完整工具组、安全边界和桥接 ACK 仍由原通道控制；确认后原子转入规范历史，稳定 `instructionId` 保持渲染身份，不重复显示或提交。展示索引不进入模型请求、压缩、快照和 native 会话指纹。
- 运行中待发项不提供会破坏投递的撤回入口；停止、失败或确认不明时，普通气泡下方保留轻量未送达状态。最后一条未送达消息复用普通“撤回”操作恢复草稿及附件、技能；维持 Stop 不自动重新发送的既定语义。
